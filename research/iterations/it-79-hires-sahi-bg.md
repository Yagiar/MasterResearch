# ИТЕРАЦИЯ 79 — SAHI-FP на крупноразрешающих чистых фонах (Open Images): закрытие бэклога `hi-res-bg-for-sahi-fp` (предрегистрация 21.09; завершена 22.09)

- **Дата:** 2026-09-21…22. **Статус:** ЗАВЕРШЕНА 22.09 (X0 зелёный; X1/X2 красные — FP AND@0,40 не робастна к HD+SAHI; см. «Результаты»).
- **Триггер:** постскриптум it-73: на локальных COCO-фонах (≤640 px) SAHI тождественен
  full-frame ⇒ W4 («SAHI-FP») была неизмерима. Также это первая проверка устойчивости
  FP-доказательства ансамбля AND@0,40 (V1=7,2 % измерено на 640-px full-frame) к режиму
  входа «HD-кадр + тайлинг».

## Источник данных (зафиксирован ДО чисел; верифицирован HEAD-запросами 21.09)

- Open Images v5/v6 validation: список `https://storage.googleapis.com/openimages/2018_04/validation/validation-images-with-rotation.csv`
  (ImageID, OriginalURL Flickr, License per-image, OriginalSize); аннотации
  `openimages/v5/validation-annotations-bbox.csv`; классы `v5/class-descriptions-boxable.csv`.
- Фильтры отбора (детерминированные, сид 20260921): (1)OriginalSize min-сторона ≥ 768;
  (2) License строка содержит `creativecommons` (CC BY/BY-SA/BY-NC; «all rights reserved» — отсев);
  (3) исключение кадров с любым bbox-классом aerial-семейства по точным кодам из
  class-descriptions: Airplane, Helicopter, Drone/UAV (если есть в листе), Kite, Parachute,
  Hot air balloon, Balloon; (4) случайная выборка 400 + резерв 150 (битые Flickr-URL ожидаемы).
- Постфильтр по факту (блокатор): PIL-проверка фактических пикселей min≥768 у 100 % принятых;
  класс-проверка повторная по скачанным аннотациям; дубликаты по MD5 — отсев.
- Лицензионная рамка: только локальное научное использование; перераспределения изображений
  нет (в git не попадают, `data/_prepared` вне репозитория); аннотации OI CC BY 4.0.
- Контаминация: ни old (майские UAV-веса), ни new (uav-yolov8s-bg+MMAUD) не обучались на OI;
  COCO-негативы в текущих весах отсутствуют (плечо bg70 на паузе) — источник независим от V1.

## Протокол замера

Тот же tile-протокол, что it-73 (`it73_coco_sahi_fp.py --file-list`, слайсы 640, overlap 0,2,
conf 0,05, NMS внутри кадра по max_conf; GPU, device cuda, venv MasterDiploma). Выход —
`img,n_boxes,max_conf` на кадр для old и new; ряды ансамбля: AND_τ := min(max_conf_old,
max_conf_new) ≥ τ, OR — max (конвенция it-74 на уровне «кадр-максимум»).

## Предрегистрированные критерии

- **X0 (блокатор выборки):** принято ровно 400 кадров; 100 % с фактической min-стороной ≥768;
  ноль aerial-классов в финальной выборке; 100 % лицензии CC*. Не выполнено — вердикт не выносится.
- **X1 (главный критерий ансамбля):** FP(AND@0,40; SAHI-HD) ≤ 12,8 % (порог E1/V1).
- **X2 (consistency с V1):** |FP(AND@0,40; SAHI-HD) − 7,2 %| ≤ 8 п.п. (диапазон Φ it-76).
- **X3 (справочно):** FP old@{0,4;0,5}, new@{0,4;0,5}, OR@0,4; медиана тайлов/кадр; доля кадров
  с птицами в аннотациях (страта интерпретации, не критерий).
- **Правило вердикта:** X1∧X2 (при зелёном X0) → FP-доказательство AND@0,40 робастно к режиму
  входа (full-frame 640 → SAHI HD); W4-ось реестра закрывается измеренным фактом для ансамбля.
  Красный X1 или X2 → регистрируется НОВОЕ ограничение профиля: в HD/SAHI-режиме FP-профиль
  ансамбля смещается (число и знак — из замера); на вердикт it-73 (W2 красная) не влияет.

## Ограничения (заранее)

1. Flickr-домен: разрешения/сюжеты не из UAV-распределения — это и есть смысл «чистого фона»,
   но темп FP может отличаться от оперативных сцен (небесные кадры с птицами/линиями — отмечаем стратами).
2. Один прогон на модель (сид застройки выборки 20260921), дисперсии режима нет.
3. Ориентация тайлинг-геометрии: для сторон >640 SAHI даёт ≥2 тайла ⇒ метрика несопоставима
   с V1 напрямую — поэтому сравнение через диапазоны X1/X2, а не тождество.
4. Масштаб затрат: до ~800 MiB–2 GiB диска на 550 картинок; тайловый инференс линейен по площади.

## Результаты (22.09.2026)

**X0 — выполнен:** принято ровно 400 HD-кадров Open Images (validation, Flickr OriginalURL),
фактическая min-сторона 768–4032 (PIL-замер по факту загрузки), 100 % лицензий CC, ноль
aerial-классов; пересечение old∩new = 400. Замеры интерпретируемы.

FP %, τ × ряд (кадр-максимум max_conf по SAHI-тайлам 640/overlap 0,2; n=400):

| τ     | old  | new  | AND  | OR   |
|-------|------|------|------|------|
| 0,30  | 92,8 | 62,8 | 61,5 | 94,0 |
| 0,35  | 90,0 | 54,5 | 52,8 | 91,8 |
| 0,40  | 86,2 | 50,5 | 48,8 | 88,0 |
| 0,45  | 80,5 | 44,5 | 41,5 | 83,5 |
| 0,50  | 75,0 | 37,8 | 34,2 | 78,5 |

- **X1 (главный): КРАСНЫЙ.** FP(AND@0,40; SAHI-HD) = 48,8 % ≫ 12,8 %.
- **X2 (consistency с V1=7,2 %): КРАСНЫЙ.** |48,8 − 7,2| = 41,6 п.п. ≫ 8,0.
- **X3 справочно:** медиана тайлов/кадр = 24 (среднее 28,4; диапазон 4–96); среднее срабатываний/кадр
  old = 48,2, new = 12,9; доля кадров с птицами в аннотациях OI = 1,2 % (страта пренебрежима);
  old доминирует по галлюцинациям и в HD-режиме.

**Вердикт (по предрегистрированному правилу):** красные X1/X2 → регистрируется НОВОЕ
ограничение профиля ансамбля: **FP-точка AND@0,40 не робастна к режиму входа.** На 640-px
COCO-фонах (V1, it-73) FP = 7,2 %; на чистых HD-фонах при нативном разрешении тайлов —
48,8 %. Механика: медиана 24 тайлова воздействия на кадр (до 96) против одного full-frame 640
в V1, т. е. на 1–2 порядка больше, и per-frame max_conf растёт как 1−(1−p)^m; плюс HD-тайлы
показывают модели нативное разрешение (мелкие структуры), которого не было в 640-px входе
обучения. Знак смещения (+41,6 п.п.) совпадает у обеих моделей и ансамбля → эффект режимный,
не модельный. На вердикт it-73 (W2 красная: SAHI-приём в контуре) не влияет. Ось W4/robustness
закрывается измеренным фактом: **в HD/SAHI-режиме требуется перекалибровка порога τ
(AND@0,45–0,50 даёт 41,5–34,2 % — всё ещё выше 12,8 %; целевой FP на HD достигается только
ростом τ, а не сменой режима).** Ограничение it-73 «неизмеримо на HD» снимается — измерено.

## Процесс (инфраструктурная сага загрузки — честно)

1. Зеркала OI закрыты (403 на originals/web/images/web/validation/data/validated) →
   единственный источник — Flickr `_o` URL из манифеста OI; ~86–90 % партий 2018_04 мертвы (404).
2. Edge Flickr троттлит и urllib, и curl при устойчивом трафике; бан цикличный: шторм 429
   ~30 мин → окно полного 200-сервиса ~10 мин (окна давали +11…+34 кадра). Эволюция транспорта:
   urllib+экспоненциальный бэкофф (run-3 простоял 15 мин в nanosleep) → curl-субпроцесс,
   арифметический бэкофф 10/20/30 с → DELAY 0,4→1,2→4,0 с с джиттером ×[0,8;1,4] → dead.txt
   (bootstrap 27 трупов из манифеста + подтверждение при второй проверке; экономия ~2000
   холостых запросов) → circuit breaker (15 не-OK подряд → дрем 1200 с; активная ходьба
   удлиняет бан). Итог run-7: 400 принято за 815 попыток, 271 сбойная-загрузка, 117 small.
3. Нелиггодные альтернативы HD-источника отсеяны доказательно: COCO S3 — только http и
   деградирован (~10 с/файл); локальный val2017 — официальная 640-px версия (0/5000 min≥768)
   = тот же материал, что V1; hf-drone-detection — 640×480; sandbox-видео — DUT-домен.
4. Автоцепочка замера после `ACCEPTED=400/400` упала на баге обвязки (`--images-dir` без
   подпапки `images/` → cv2 None); протокол не затронут, перезапуск тех же команд — ок.
   Время сбора: 21.09 22:38 → 22.09 08:47 UTC (~10 ч, фоном).
