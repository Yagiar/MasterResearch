# ИТЕРАЦИЯ 52 — Целевая переменная зафиксирована (presence|airborne) + признак движения трека; наивная скорость недостаточна на близком плане

- **Дата:** 2026-09-05
- **Источник:** санкционированная альтернатива it-51 (MMAUD заблокирован): зафиксировать целевую переменную и добавить признаки состояния/движения для «airborne»-дискриминации (ревью §3).
- **Артефакты:** `libs/common/.../messages.py` (`QualityHint.motion_score`, аддитивно), `visual_detector/consumer.py` (скорость трека), `fusion/target.py` (фильтр цели) + `fusion/consumer.py` (`fusion.target`, `fusion.motion_floor`), `configs/pilot.yaml`, `fusion/tests/test_target.py` (+6), `research/target_validate_run.sh`.

## Реализация

1. **Целевая переменная зафиксирована в конфиге**: `fusion.target: presence | airborne` (дефолт presence — прежнее поведение). В режиме `airborne` видео-подтверждение засчитывается только при движении трека: `apply_target_filter()` переводит best_video с `motion_score < motion_floor` в «non-drone» (статичная цель = «не активный БПЛА»); при неизвестном motion (трекер выключен) фильтр не рискует — окно не меняется (документировано).
2. **Признак движения**: visual-detector ведёт историю центров трека (8 позиций, per source+track_id); `motion_score` = средняя скорость центра, нормированная на 0.25 ширины кадра/с, кламп [0,1]. Пробрасывается в `QualityHint.motion_score` → fusion.

## Распределение признака (негативная сессия, стоящий дрон крупным планом)

По видео-сообщениям (n=300): **медиана 0.004, p90 0.154, max 0.190** — разделение со «полётом» возможно в принципе, но хвост тяжёлый: до 10% окон статики имеют motion ≥ 0.15 (джиттер bbox крупного плана).

## Живая валидация (негативная сессия, GT airborne=0, watermark k5 Δ0 τ0.5)

| Конфигурация | FP для цели airborne |
|---|---|
| без фильтра (it-51 B) | 24.3% |
| target=airborne, motion_floor=0.15 | 21.2% |
| target=airborne, motion_floor=0.20 | 21.3% |

**Вывод: наивная скорость bbox недостаточна.** FP распределяются равномерно по прогону (~10–14% на 30-с бакет), а не только в стартовом транзиенте: на близком плане джиттер bbox переводится в высокую «скорость» (детекторный шум масштабируется с размером бокса), и часть статичных окон получает motion ≥ floor. Замер распределения подтверждает тяжёлый хвост (p90=0.154 при floor 0.15; в других окнах хвост за 0.2).

## Что зафиксировано как достижение

1. Целевая переменная больше не скрыта в интерпретации: `fusion.target` явен, логируется на старте, тестируется (it-51 сценарий: presence → True, airborne → False на одних данных).
2. Признак состояния реализован и измерим; его распределение на статике (медиана 0.004) показывает принципиальную разделимость.
3. Инфраструктура эксперимента (target_validate_run.sh) переиспользуема для калибровки motion_floor на независимом материале.

## Следующие шаги для «airborne»-дискриминации (it-53+)

1. Нормировка джиттера на размер бокса (speed_rel = speed / bbox_w) или оптический поток вместо скорости центра; калибровка floor по распределениям статика/полёт на независимом материале.
2. Аудио-подтверждение как обязательное для airborne-цели (мотивируется it-51: FP окна имели выбег винтов) — гибрид «видео-присутствие ∧ аудио-активность».
3. MMAUD при интерактивной загрузке (блокер it-49) — и для калибровки, и для внешней валидации.
