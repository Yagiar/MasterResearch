# it-82 — Живой фоновый прогон: FP-обещание ансамбля в контуре (ПРЕДРЕГИСТРАЦИЯ 22.09, до любых замеров)

**Гипотеза.** Офлайн-обещание AND-ряда ансамбля — подавление ложных срабатываний
(V1 it-69: new@0,4=10,2 % против old@0,5=27,5 % на 400 COCO-фонах, режим 640 full-frame;
grid it-74: AND@0,40 = 7,2 %) — воспроизводится в ЖИВОМ контуре: на видеопотоке из HD-фонов
без дрона доля положительных решений в плече AND@0,4 строго ниже, чем в плече off (одиночный old).

**Зачем (дыра после it-81).** Живой A/B it-81 показал нейтральность всех трёх плеч (P 0,927 /
R 1,000 / F1 0,962), но его материал не содержал фоновых окон: FP там нечего было мерить —
AND «не резал» потому, что резать было нечего. Единственный живой тест FP-подавления —
поток из заведомо бездронных кадров. Это прямое дополнение it-81 (тот же конвейер, тот же
runner, противоположный по знакочувствительности материал), а не повтор.

## Материал и механизм (разведка 22.09, до предрегистрации)

- Кадры: `MasterDiploma/train/data/_prepared/hi-res-bg-v1` — 400 HD-изображений Open Images
  (min сторона 768…4032 px; отбор/CC/¬aerial — it-79, §6k REPRODUCE). В `images/` лежат 412
  файлов, включая 12 отвергнутых → собирается **strict400**: симлинк-каталог ровно по
  `filelist.txt` (400), порядок — сортировка по имени (так читает `MmaudReplayAdapter`).
  Тот же материал, на котором измерены офлайн FP-ряды it-79/80 — живое число будет сравнимо
  с офлайном «плечо в плечо» (внимание: режим входа живой детекции — full-frame, не SAHI;
  офлайн-пара 7,2 % — 640-режим COCO/V1; прямое численное совпадение не ожидается и не требуется,
  сравнение предрегистрировано как **относительное внутри прогона**).
- Поток: `adapter: mmaud_replay`, `audio_path: null`, `enable_audio: false` (прецедент env-оверлеев
  it-59: `UAVDET_SOURCE__ADAPTER`, `UAVDET_SOURCE__MMAUD_REPLAY__VIDEO_PATH`, `..._FPS`),
  `loop: true`, `fps: 2` → 240 с ≈ 480 кадров = 1,2 прогона каталога (первыми 80 дублей;
  множитель повторной экспозиции ×1,2 фиксируется, unit-анализ по media-секундам).
- Акустика без входа → health-механизм вырождает решение в video-only (it-60/61) — ожидаемо
  и есть предмет замера: положительное решение на бездронном материале = FP целиком видео-ветки.
- Fusion во всех этапах — боевая поставка, идентично it-81: watermark, max_wait 5000 мс,
  k=5, τ=0,5, Δ=0. Различие этапов — только `VOTE_MODE/FLOOR` visual-detector'а.

## Этапы (порядок фиксирован A→B→C, по 240 с, burn-in 60 с)

| этап | vote | ожидаемый `model_name` (P3-гейт по данным) |
|---|---|---|
| A baseline old-only | off | `^yolov8s-uav$` |
| B AND@0,4 (voter=new) | and, floor 0,4 | `^yolov8s-uav\+uav-yolov8s-bg-best:and@0\.4$` |
| C OR@0,4 (voter=new) | or, floor 0,4 | `^yolov8s-uav\+uav-yolov8s-bg-best:or@0\.4$` |

Веса: old `models/visual/yolov8s-uav.pt` (sha `41f3fd55…a262`), voter
`models/visual/uav-yolov8s-bg-best.pt` (sha `7042602a…37493`) — sha печатаются в лог runner'а (P4).
Runner — адаптация `it81_ab_run.sh`: +оверлей источника (mmaud_replay на strict400, без аудио,
volume `../train/data/_prepared/hi-res-bg-v1/strict400:/data/bg:ro`), сохранены гейты it-81:
create_topics + стрим-гейт 25 с, build образа, P-гейты env и model_name по данным.

## Критерии (предрегистрированы, зелёный = все; честный null допускается)

- **P0 (разделимость материала):** FP(A) > 0, т.е. одиночный old даёт хотя бы одно
  положительное окно за этап. Если FP(A) = 0 — вердикт «живого FP у old-ряда на этом материале
  нет, обещание ансамбля в контуре негде себя показать» (тоже результат, абсолютные числа
  фиксируются; критерии P1/P2 помечаются n/a).
- **P1 (эффект AND):** FP(B) < FP(A) — строго меньше; считаются биномиальные ДИ Уилсона
  на долю положительных media-окон, перенос выводов при перекрытии ДИ не утверждается, а помечается.
- **P2 (направленность OR — контроль):** FP(C) ≥ FP(A) (OR добавляет срабатывания; если нет —
  атрибюция механизма под вопросом, фиксируется).
- **P3 (атрибуция конфигурации по данным):** на каждом этапе `DISTINCT model_name FROM
  uavdet.inference WHERE modality='video'` равен ожидаемому (урок it-81: env не доказывает код).
- **P4 (provenance):** sha весов в логе; топики созданы; стрим-гейт 25 с пройден.
- **P5 (env-гейт):** vote-переменные в контейнере visual-detector напечатаны до измерений.

## Метрика

Единица — media-секундное окно fusion (шаг 0,5 с, как it-68/81), знаменатель — окна этапа после
burn-in 60 с, числитель — окна с положительным решением presence. GT тривиален: все окна
отрицательны (дрона в материале нет; подтверждение: ни одного трека с p_a-подтверждением).
Артефакты: `research/it82_bg_fp.csv` (этап, окна, положительно, доля, ДИ),
`research/it82_bg_summary.txt` (provenance+вердикты), лог `research/it82_bg_run.log` (gitignored).

## Риски / ограничения (фиксирую ДО)

1. HD-кадры в живом full-frame (imgsz детектора 640) — даунскейл большой цели→мелкая: офлайн
   old@0,5 на 640-COCO-фонах 27,5 %, но OI-фоны не COCO — абсолют не переносится, только сравнение внутри.
2. fps=2 → 1,2 петли: дубли 80 кадров в начале этапов смещают состав одинаково во всех плечах
   (один и тот же порядок) — на относительное сравнение не влияет.
3. Повторы одного кадра в потоке ≠ независимые окна (автокорреляция FP по кадру) — ДИ Уилсона
   завышают значимость; в вердикте это оговаривается явно (практика it-40 «окна не независимы»).
4. Акустика выключена → это NOT боевой мультимодальный профиль, а изолированный замер видео-FP;
   в отчёт идёт с этой рамкой.

## Ожидаемый итог и что дальше

Зелёный P1: «FP-подавление ансамбля подтверждено в живом контуре» — усиливает SYNTHESIS-пункт 8
(it-81 нейтрален по R; теперь и FP-обещание проверено). Красный P1 при зелёном P0: «живой FP
не подавляется AND@0,4» — офлайн-сетка не переносится в контур, ограничение профиля.
Нулевой P0: живой контур на этом материале не порождает FP у одиночного old — FP-проблема
оказывается чисто SAHI/HD-модусом (it-79/80), контурного подтверждения FP-рядов нет и не нужно.
