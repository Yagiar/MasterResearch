# it-70 — Рычаг рецепта корпуса: разбавление фоновых негативов (вариант A)

**Статус: 🟡 запущена (предрегистрация 2026-09-21, до любых прогоновых метрик it-70).**
План. Факты и вердикты — в этом файле по мере работ; финал → `it-70-….md` (rename), строка в `INDEX.md`, манифест.

## Предистория (наследование)

- it-65: дообучение YOLOv8s на корпусе DUT+COCO-фоны (негативы 1,26 % train / 3,3 % val / 1,8 % test)
  убило FP (V1 it-69: @0,25 61,8 %→17,8 %; @0,5 27,5 %→6,5 %) и дало E5-красный:
  SAHI-recall полёта MMAUD @0,5 = 84,3 % < 89,5 %.
- it-69 (шаг 0 + V1/V2/V3): механизм E5 — сдвиг conf-распределения новых весов вниз на ~0,1
  (пересчёт τ-сетки из per-frame CSV: τ=0,4 → 94,8 %; τ=0,25 → 99,4 %). Перекалибровка
  операционной точки офлайн подтверждена (V1/V2 зелёные), но в контуре не проходит (V3 красный:
  боевой гейт уже 0,25; потери airborne-окон — оконная логика fusion, не порог). Вывод it-69:
  «починка — на уровне рецепта корпуса».
- Хвост it-65 (бэклог, дословно): «снизить долю фоновых негативов (1,3 % → ~0,3–0,5 %) …
  Проверять той же вердикт-машинкой E1–E5 с новой предрегистрацией порогов».

## Гипотеза (формулировка)

Мы claim, что **снижение доли фоновых негативов COCO в обучении с 1,26 % до ~0,4 %**
(300 из 900 кадров, всё остальное — бит-в-бит корпус и гиперпараметры it-65)
поднимает SAHI-recall полёта MMAUD @0,5 новых весов до ≥ 89,5 % (E5),
сохраняя FP-подавление на независимых фонах (E1) и метрики домена (E2–E4),
против базы: старые майские веса (E5 = 94,5 %, FP@0,5 = 27,5 %) и веса it-65
(E5 = 84,3 %, FP@0,5 = 6,5 %). Job новой модели — вернуть recall, не потеряв FP.

Варианты B (distant-негативы из MMAUD) и C (двухстадийная доводка) — вне it-70
(одна изменённая вещь за раз; регистрация при красном A).

## Механизм изменения (единственный рычаг)

1. Корпус `_prepared/visual` it-65 детерминирован (`RANDOM_SEED=1337`, команды в `REPRODUCE.md`);
   перетирать prepare-visual НЕ будем — текущее состояние и есть it-65-корпус (проверка счётчиков 57366/2690/4915, фоны 720/90/90).
2. **Уточнение протокола ДО прогонов (2026-09-21, dry-run QA):** первый вариант keep-списка
   (`Random(1337).sample(900, 300)`) выявил структурную корреляцию с `_split_groups` (тот же сид 1337):
   все 180 val/test-фонов попали в keep, train-фоны упали до 120 — нестратифицированная доля.
   Исправлено на стратифицированный прунинг независимым сидом: keep-списки режутся отдельно
   в каждом сплите, `random.Random(20260921)`: train 720→240, val 90→30, test 90→30
   (ожидается train-доля ≈ 0,42 %, val ≈ 1,1 %, test ≈ 0,6 %). Метрик it-70 ещё не видели —
   правка предрегистрации, не результатов.
   Скрипт-дроп `research/it70_prune_negatives.py` (по исходным stems `coco_bg_*` из prepared-имён
   `coco-background_{orig}_{i:07d}_{orig}`); keep-list — артефакт `research/it70_neg_keep.txt`
   (в манифесте, sha фиксируется). Исходники `train/data/coco-background/val2017` не трогаем;
   полный корпус восстанавливается командой prepare-visual it-65.
3. Тренировка — команда it-65 дословно, кроме `--name uav-yolov8s-bg70`
   (epochs 30, patience 10, batch 8, workers 2, base yolov8s.pt, imgsz по умолчанию).

- E1–E5 — образцы прогонов it-65 (те же скрипты/пороги, где применимо; E1 — вместо 90-кадрового
  теста it-65 берём независимые 400 V1, как и обещано уроком независимости).
- E6–E8 — прогон инференса новыми весами по песочным кадрам (imgsz 480, тот же протокол,
  что `yolo_sandbox_frames_new.csv`), далее 5 fusion-скриптов с `--suffix=-bg70` на гейте 0,25
  (фильтр max_conf<0,25→0 на уровне предфильтра, как в V3 it-69; на этом материале гейт 0,25
  не no-op в отличие от 0,4 — проверим и доложим честно).
- Одиночная семка тренировки — ограничение фиксируем в отчёте (стоимость ~сутки GPU; практика it-65).

## Правило вердикта (предрегистрировано)

Все E1–E8 зелёные → экспорт пары (чекпойнт it-70 + гейт 0,25 без изменений) разрешён:
`uavtrain evaluate/export`, фиксация sha, `models/registry.csv`, `models/README`, замена
боевых весов только после одобрения автора. ЛЮБОЙ красный → веса остаются майские,
в отчёте — честная констатация (вариант A исчерпан → бэклог B/C).

1. Прунинг + keep-list + счётчики в лог. (CPU, минуты)

3. Замеры E1–E5 (по образцу it-65: eval-прогоны dut600/hf600, coco_bg_fp_eval на V1-400, session probe, MMAUD SAHI).
