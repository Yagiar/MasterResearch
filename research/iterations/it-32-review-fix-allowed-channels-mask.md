# ИТЕРАЦИЯ 32 — Фикс по ревью: маска допущенных каналов в late/hybrid (§6.4)

- **Дата:** 2026-09-05
- **Источник:** внешнее ревью GPT-6-Astra (`review-from-gpt-6-astra/MasterResearch_review.md`, п. 6.4; контрпримеры `zero_audio_weight_does_not_remove_audio_effect` в `reviewer_checks.py`).
- **Компоненты:** `services/fusion/src/fusion/strategies/late.py`, `strategies/hybrid.py` (докстринги + арифметика), новый `tests/test_strategies.py` (+13 тестов — стратегии раньше напрямую не покрывались).

## Дефект (подтверждён по коду)

«Активность» канала определялась **наличием детекции в окне**, а не допущенностью после gating/health-gate:

1. `LateFusion`: Δ-бонус/штраф применялся при наличии обоих сообщений, даже если `w_a` обнулён гейтом → аудио «не участвуя», меняло решение. Контрпример рецензента: `p_v=0.55`, аудио-«не-дрон», `w_a=0`: `0.55 − 0.1 = 0.45` → отрицательное решение, хотя video-only положителен.
2. `HybridFusion`: в двухканальной ветке веса брались как есть (без перенормировки), вероятностное ИЛИ и штраф не зависели от `w_a=0`. Контрпример: `p_v=0.9, w_v=0.5, w_a=0`, аудио противоречит: `0.45 − 0.15 = 0.30` → False при video-only True.

Это ломало обещанный семантику health-gate: «закрыл гейт → решаем по видео».

## Решение

Введена **маска допущенных каналов**: канал допущен ⟺ детекция в окне И вес > 0.

- `LateFusion`: Δ-правило — только между допущенными каналами; перенормировка по допущенным (уже была, теперь на правильной маске); `p_a/p_v` в `FusionOutcome` = None для недопущенных (в jsonl/PG закраренные окна больше не выглядят «смешанными» — синергия с фиксом счётчика mixed, it-35); если не допущен ни один канал → `None` («недостаточно данных»).
- `HybridFusion`: две одноканальные ветки работают по маске; в двухканальной веса перенормируются; ИЛИ/штраф — только по допущенным; ноль допущенных → `None`.
- Докстринги уточнены: «гибрид» = нелинейная комбинация **решений**, не слияние признаков (замечание ревью §9 — зафиксировано в коде уже здесь).

## Инварианты (тесты)

- Контрпримеры рецензента: late `0.55−0.1=0.45` → стало `0.55/True`; hybrid `0.30` → стало `0.9/True`.
- Инвариант «закрытый канал не влияет»: перебор p_a∈{0.01…0.99} при `w_a=0` — `p_fused` неизменен.
- Регрессы: штраф/бонус при допущенном аудио работает как раньше; отсутствующее аудио (молчание) — прежняя перенормировка; `VideoOnly` не изменился.

## Результат

**40/40 passed** (весь монорепо: libs/common + все сервисы), ruff чист.

- `AudioOnly` игнорирует `w_a` по построению (baseline); решение гейта «закрыть аудио» в режиме audio-only не применяется — заведомо, это режим сравнения, а не рабочий. Зафиксировано здесь как известное поведение.
