# ИТЕРАЦИЯ 35 — Фикс по ревью: медиа-время до decisions, скоринг без подгонки фазы по GT (§5.2/§5.3)

- **Дата:** 2026-09-05
- **Источник:** внешнее ревью GPT-6-Astra (`MasterResearch_review.md`, пп. 5.2, 5.3; вторая версия рецензии п. 5).
- **Компоненты:** `libs/common/.../messages.py` (`InferenceMsg.media_ts`, `DecisionMsg.media_ts` — аддитивно, schema_ver=1), `visual-detector/consumer.py` и `acoustic-detector/consumer.py` (проброс), `fusion/window_buffer.py` (выравнивание по media_ts), `fusion/consumer.py` (DecisionMsg.media_ts, Δt по медиа-времени), `libs/common/tests/test_messages.py` (+1), `services/fusion/tests/test_window_buffer.py` (+2), `research/score_stages.py` (переписан).

## Дефекты (подтверждены по коду)

1. **Скоринг подгонял фазу по тестовой разметке** (`score_stages.py`): перебор 41 сдвига ±5 с вокруг wall-clock `ts` решения с выбором максимума F1 на той же разметке, которую оцениваем. Плюс `ts` решения — момент публикации (`time.time()`), т.е. время обработки, а не события: оценка зависела от задержек конвейера, и постоянный сдвиг не исправляет переменную задержку очередей.
2. **Счётчик `mixed` считал только наличие `p_a`** — аудио-only окна попадали в «смешанные»; доля действительно совместных окон (аргументация it-30) завышалась.

## Решение

1. **Проброс медиа-времени до конца конвейера**: детекторы копируют `media_ts` из RawMsg в `InferenceMsg`; fusion выравнивает окно по `_align_ts(msg)` = `media_ts`, если отдан, иначе wall-clock `ts` (совместимость со старыми продюсерами); `DecisionMsg.media_ts` = событийное время триггер-сообщения; метрика Δt — по шкале выравнивания.
2. **`score_stages.py`**: режим по умолчанию — `clip_time = media_ts % CLIP` с ФИКСИРОВАННОЙ фазой (media_ts=0 = старт клипа в симуляторе): никакого перебора по GT. Прогоны без media_ts (it-30 и ранее) явно пропускаются со счётчиком. Прежний перебор сохранён только под явным флагом `--fit-phase` с маркировкой «РЕЖИМ ПОДГОНКИ ФАЗЫ ПО GT (диагностика!)» в выводе — для диагностики дрейфа задержки, не для сравнения методов (по требованиям ревью: перебор допустим как диагностика, не как окончательный протокол).
3. **`смешанных` = p_v не None И p_a не None** (обе модальности участвовали; после it-32 недопущенные каналы дают None — счётчик согласован с маской).

## Тесты / проверка

- Контракт: media_ts аддитивен в 4 схемах (round-trip JSON, старые сообщения → None).
- Буфер: видео, «застрявшее» на ~990 с в доставке при общем media_ts, образует совместное окно; окна в шкале media_ts; без media_ts — прежнее поведение.
- На живом jsonl it-30: дефолт-режим честно сообщает `usable(media_ts)=0` (прогон до фикса), `--fit-phase` работает; смешанных окон этапа A на срезе 1:200 — 30 (обе модальности), раньше считались все с p_a.

**58/58 passed** (монорепо), ruff чист по затронутым файлам.

## Ограничения

- Новый скоринг применим только к прогонам ПОСЛЕ it-34/35 (нужен GPU-прогон — заблокировано тем же окружением, что it-30); сравнение с числами it-30 напрямую невозможно — это другой измерительный протокол.
- Фаза media_ts=0 фиксируется стартом симулятора; если клип стартует с произвольного места, потребуется явный `clip_offset` в конфиге источника (не требуется для текущего sandbox-прогона).
