# it-83 — Фикс media_ts в режиме папки (mmaud_replay) + регресс + живой sanity (ПРЕДРЕГИСТРАЦИЯ 24.09, до чтения замеров)

**Гипотеза.** Найденный в it-82 дефект таймбейса (в режиме папки `media_ts` считается по
номинальным 30 Hz, а темп отправки — по `requested_fps`; при 2 к/с медиа-таймлайн сжат ×15:
240 с wall → 18,3 с media) устраняется однострочным фиксом «таймбейс папки = requested_fps»,
и после него живой прогон даёт media/wall ratio ∈ [0,8; 1,2], не переворачивая направление
FP-эффекта (AND < old).

**Происхождение.** Пункт P0 внешнего аудита 24.09 (`DECISION-roadmap-post-it82.md`): фикс
media_ts — блокер для it-84 (paired replay) и it-86 (синхронный мультимодальный негатив),
пока единица «media-секунда» в режиме папки не является единицей.

## Живой sanity (короткий A/B, НЕ новый вердикт ряда)

Runner `research/it83_sanity.sh` — каркас it82_bg_run.sh (те же гейты: build образов,
create_topics, P5 env, стрим-гейт 25 с, P4 model_name по данным; оверлей strict400, fps=2,
без аудио), этапы A off → B AND@0,4 по WAIT=120 с. Разбор `research/it83_sanity_eval.py`.

**Критерии (предрегистрированы, зелёный = оба):**

- **S1 (таймбейс):** для обоих этапов ratio = (max−min media_ts)/(max−min ts) ∈ [0,8; 1,2].
  На старых (дофиксовых) срезах it-82 скрипт даёт ratio 0,067–0,075 🔴 — самопроверка
  направленности метрики выполнена на независимом (старом) данных до запуска.
- **S2 (непереворот эффекта):** кадровая FP-доля (уникальный media_ts, burn-in 60 с)
  FP(B) < FP(A). Абсолютные значения sanity не канонизируются (этап короткий); направление —
  контроль, что фикс не изменил семантику решений.

Красный S1 при зелёных гейтах = фикс не в образе (урок it-81: код в образе, не mount) —
атрибуция через лог сборки; фиксировать, не перекалибровывая диапазон.

## Риски (фиксирую ДО)

1. Sanity-прогон короткий (~100 кадров после burn-in) — недостаточен для новых числовых
   рядов; он ничего не утверждает кроме S1/S2 (это не «повтор it-82»).
2. Изменение таймбейса сдвигает смысл старых артефактов it-57…82 (media_ts там сжат);
   нумерация итераций не переписывается — в отчётах это остаётся с пост-хок оговоркой it-82,
   боевые канон-числа (P/R/F1, кадровые FP) от таймбейса не зависели.
3. `ts_window` fusion теперь реально шириной 1,2 с при шаге 0,5 — в sanity считается
   по кадрам (уникальный media_ts), слотная метрика не используется (иначе смешение режимов).
