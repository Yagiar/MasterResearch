# ИТЕРАЦИЯ 57 — ROSBag получен, аудио извлечено; независимая акустическая калибровка: AST не переносится на distant-drone rooftop-домен (p_drone ≈ 0.075 везде)

- **Дата:** 2026-09-06
- **Источник:** пользователь скачал «ROSBag Data» DJI Mavic3 V1 (Mavic3.bag, 11.9 ГБ, 198.4 с).
- **Артефакты:** `research/mmaud_acoustic_eval.py`, `research/mmaud_acoustic_eval.csv`, аудио `research/mmaud_audio1_6k.wav` (6 кГц оригинал) и `_16k.wav` (ресемпл для AST) — на диске.

## 1. Извлечение аудио из ROSBag

Bag содержит 4 канала микрофонной решётки (`/audio1..4/audio`, audio_common_msgs/AudioData, 8266 сообщений × 144 int16-сэмпла = **6 кГц на канал**, Найквист 3 кГц) + лидары/радар/камеру. Извлечён канал audio1: 207.3 с, RMS 0.562 (сигнал горячий), ресемпл 16 кГц для AST.

## 2. Независимая акустическая калибровка (GT-высота: z<0.5 стоит, z>1 летит; 413 окон 1с/0.5с)

| Состояние | n окон | p_drone медиана | p90 | доля ≥0.5 |
|---|---|---|---|---|
| СТОИТ (на земле у пусковой) | 28 | 0.078 | 0.119 | 0.0% |
| ЛЕТИТ (в воздухе, до 9 м) | 383 | **0.075** | 0.105 | **0.0%** |

**Recall 0%, FP 0% — AST ниже порога везде.** Независимая акустическая калибровка дала предельный ответ: модель не переносится на этот домен вовсе.

## 3. Санити-проверки (исключают «сломанный инструмент»)

- Все 4 канала идентичны: RMS 0.560, клиппинг ~1% — микрофонная решётка перегружена равномерно (ветер/шум крыши, усиление велико; max амплитуда 32766/32768).
- Контент wav верифицирован (извлечение из bag напрямую, не нарезка).
- Полоса 6 кГц (Найквист 3 кГц) — гармоники винтов выше 3 кГц недоступны;AST обучен на 16 кГц close-mic записях.
- Домен: дрон на удалении до 9 м и выше + громкий шум крыши — вне распределения DADS.

Каждый из факторов (перегруз, полоса, дистанция, шум) достаточен для отказа; их совокупность делает отказ AST на этом материале ожидаемым и объяснённым.

## 4. Следствия для системы и диссертации

1. **Политика it-55 ведёт себя корректно в этом домене**: p_a < 0.3 везде → аудио-подтверждение не даёт ложных срабатываний (FP от аудио = 0), но и recall от аудио = 0 — система честно вырождается в video-only (это и есть работа health-механизма: громко + нет отклика модели = канал недостоверен, it-16/19).
2. **Независимый материал окончательно опровергает перенос обеих модальностей без адаптации**: видео — масштабный доменный разрыв (recall 18% @960 → 64.5% @1920, it-56), аудио — полный отказ (p_drone ≈ 0.075 везде). Формулировка для диссертации: «перенос на независимые сценарии требует доменной адаптации каждой модальности; наивная система без адаптации неработоспособна».
3. Акустическая ветвь нуждается в дообучении на distant-drone данных (6 кГц полоса + шум крыши) либо в отказе от акустики для таких сценариев.

## Ограничения

- 6 кГц аудио: калибровка измеряет AST именно на этой полосе; высокочастотную часть сигнала оценить невозможно (нет данных в bag).
- Перегруз ~1% сэмплов вносит нелинейные искажения — не устраняемы постобработкой.
- Один прогон одной секвенции V1 (Rooftop Simple); V2/V3 (Carpark) — аналогичные загрузки при необходимости.
