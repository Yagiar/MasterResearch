# ИТЕРАЦИЯ 05 — AST офлайн по окнам аудио: P/R/F1 против GT

- **Дата:** 2026-09-04
- **Цель:** получить честные метрики акустической ветки (AST) на целевом аудио против GT-разметки (до сих пор были только «99/144 окон» из probe и with_audio из прогона).
- **Артефакты:** `research/ast_windows_eval.py`, `research/ast_windows.csv` (144 окна: t0, p_drone, label, airborne_gt).
- **Метод:** тот же рантайм, что в пайплайне (`acoustic_detector.AstAudioClassifier`, PCM 16 кГц), окна 1 с / шаг 0.5 с → 144 окна; GT окна — доля `airborne`-секунд ≥ 0.5.

## Результаты

| Метрика vs `airborne` | Значение |
|---|---|
| Precision | **0.977** (2 FP) |
| Recall | 0.766 (26 FN) |
| **F1** | **0.859** |
| Окон с p(drone)≥0.5 | 87 из 144 (60.4%) |

Профиль срабатываний совпал с разметкой: первый `p≥0.5` — t≈10.5 с (взлёт), последние — ≈65 с (посадка); на стоянках (0–10, 66–72) — тишина. Сверка с probe_audio (99/144) — небольшое расхождение (другое выравнивание окон/декодирование), качественно картина та же.

**Структура ошибок:** все 26 FN — окна в полёте, где AST дал p=0 (короткие провалы уверенности на 13–15, 24–25, 46–49, 57–62 с — вероятно, моменты тихого висения/дальнего положения); оба FP — сразу после посадки (t=68.0, 68.5, p≈0.55 — звук останавливающихся винтов).

## Выводы

1. AST на целевом домене — не «69% угадываний», а **высокоточный (P=0.977) детектор активности с умеренным recall** — совсем другая формулировка для отчёта.
2. Провалы AST короткие и не систематические → **временная консистентность (медианный фильтр по перекрывающимся окнам) должна поднять recall** — проверено в it-06 (F1 0.859 → 0.922).
3. FP на выбеге винтов после посадки — физически осмысленный крайний случай, кандидат в документацию «границ применимости».
