# ИТЕРАЦИЯ 33 — Фикс по ревью: горизонт опоздания в TimeWindowBuffer + наблюдаемость (§6.2)

- **Дата:** 2026-09-05
- **Источник:** внешнее ревью GPT-6-Astra (`review-from-gpt-6-astra/MasterResearch_review.md`, п. 6.2; контрпример `arrival_order_mixed_windows` в `reviewer_checks.py`).
- **Компоненты:** `services/fusion/src/fusion/window_buffer.py` (политика опоздания, флаги окна), `consumer.py` (метрики), `libs/common/.../metrics.py` (+2 счётчика), `fusion/__main__.py` + `configs/pilot.yaml` (`window_lateness_ms: 2000`), новый `tests/test_window_buffer.py` (+6).

## Дефект (подтверждён по коду)

`TimeWindowBuffer.add()` выселял записи старше `t − ε` в момент прихода **каждого** сообщения. Запаздывающая модальность находила окно уже опустошённым: `video@10 → video@12 → audio@10` (ε=0.6) не давал совместного окна, а `video@10 → audio@10 → video@12` — давал. Результат объединения зависел от **порядка доставки**, а не от времени событий; малое число совместных окон нельзя было списывать только на потерю сообщений — политика буфера сама их разрушала (альтернативная гипотеза ревью к it-30).

## Решение

1. **Горизонт опоздания** `window_lateness_ms` (по умолчанию 2000, конфиг `fusion.window_lateness_ms`): история обеих модальностей выселяется только старше `t − ε − lateness`. Интервал окна остаётся [t−ε, t+ε] — расширяется удержание, а не выравнивание. Для упорядоченных потоков поведение идентично прежнему.
2. **Наблюдаемость политики** (требование ревью «получено / опоздало / отброшено / использовано в совместном»): `AlignedWindow.late` (сообщение пришло за горизонтом: ts < последний − ε − lateness) → метрика `uavdet_late_messages_total`; `AlignedWindow.joint` (в окне обе модальности) → `uavdet_joint_windows_total`. Инкременты в `InferenceConsumer.process`.
3. Правило завершения окна осталось прежним (окно формируется по каждому сообщению); теперь оно дополнено явной семантикой «опоздало за горизонт».

## Инварианты (тесты)

- Контрпример рецензента: оба порядка доставки дают ровно по одному совместному окну (`counts == [1, 1]`).
- Опоздание в пределах горизонта: не флаг late, пара образуется задним числом; за горизонтом: флаг late, окно моно.
- Интервал окна не расширился; отрицательный lateness → 0 (эквивалент прежнего поведения).

## Результат

**46/46 passed** (монорепо), ruff чист (мои файлы). Незакрытые pre-existing замечания ruff (SIM105 в consumer_service, UP035 и пр.) — не из этих итераций, зафиксированы в финальном аудите.

## Ограничения

- Горизонт 2 с — эвристика: должен покрываться реальным разбросом задержек модальностей; контроль — новые метрики (доля late). «Опоздавшие за горизонт» сообщения всё равно формируют моно-окно (решение по одной модальности), а не отбрасываются.
- Эффект для it-30 (аудио доходило в 10% окон) требует нового живого прогона: если метрика `late` ≈ 0, а совместных окон мало — виноват транспорт до fusion, а не буфер.
