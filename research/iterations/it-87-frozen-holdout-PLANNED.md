# it-87 — frozen final holdout · ПРЕДРЕГИСТРАЦИЯ (протокол до открытия материала)

Дата предрегистрации: 2026-09-24. Приоритет P1-финал роадмапа (`DECISION-roadmap-post-it82.md`):
единственный подтверждающий (confirmatory) замер цикла; после него — стоп экспериментов.
Статус: **блок — материал** (новый cam+mic синхронный материал от автора; цикл не может его
сгенерировать). Прогон — на GPU-пайплайне, строго после it-85/it-88.

## Смысл

Все it-01…86 — development/exploratory evidence (адаптивное переиспользование материалов
запрещено стоп-критерием). it-87 — одна предваряемая проверка боевой линейки
(`AND_presence_live` + fusion-контур) на материале, который цикл **никогда не видел**:
открытие однократное, вердикт по предрегистрированным гейтам, красный результат не триггерит
новый τ/новую политику.

## Замороженный стек (фиксация DO, изменения после этого файла = нарушение протокола)

- веса: old `yolov8s-uav.pt` sha256 `41f3fd55…`, new `uav-yolov8s-bg-best.pt` sha256 `7042602a…`
  (полные значения — канон-блок INDEX; сверка sha в гейте H0);
- политика: `vote_mode=and`, `vote_floor=0.40` (CONF-AND@0,40) — без альтернатив;
- режим входа: живой конвейер (mmaud_replay/медиа-адаптер с корректным `media_ts` после it-83),
  `fps=2`, `loop=false`, watermark-окна fusion (`MAX_WAIT_MS=5000`, `TEMPORAL_K=5`,
  `DECISION_THRESHOLD=0.5`, `LATE Δ=0`) — каркас it-84/it-85;
- метрики: оконный FP-rate на негативах; sequence-level recall и TTD на позитивах; аудио-телеметрия
  (`modality='audio'` в inference, доля окон с audio-полем) — как обязательный отчётный блок.

## Требования к материалу (автор записывает; спецификация фиксирована)

- **Позитивы:** ≥5 независимых пролётов дрона (тот же класс аппарата допустим, но **новая локация /
  новый ракурс / новый день**), sync cam+mic, длительность каждого 1–3 мин; пометить в README
  примерные границы «дрон виден» по времени кода/секунд от начала клипа (±2 с точность достаточна).
- **Негативы:** ≥10 мин синхронных cam+mic без дрона в реалистичном уличном шуме (может совпасть
  с материалом it-86 — тогда it-86/it-87 используют разные несвязанные сегменты одной сессии,
  сегментация предрегистрируется по времени до открытия);
- материал нигде ранее не использовался (it-01…86); раскладка: `sandboxDataForSimulator/holdout-24/`
  с манифестом (файл, роль pos/neg, длительность, пометки границ).

## Гейты вердикта (предрегистрированы; односторонние, без «подкрутим после»)

- **H0 (блокаторы, до вердиктов):** sha весов совпали; материал новый (пути/хэши не пересекают
  it-01…86 входы); аудио-телеметрия живая (урок it-30/гейт M0 it-86): при включённом аудио
  audio-инференсы присутствуют; `media_ts` ratio ∈ [0,8; 1,2] на каждом сегменте (гейт S1 it-83).
  Любой H0-провал → прогон чинится и повторяется, вердиктов не существует.
- **H1 (ложные тревоги, негативы):** доля alarm-окон контура на бездронных сегментах ≤ **15 %**
  (якорь: пофреймовый paired-канон it-84 FP(B)=10,5 % на HD-фонах; 15 % — верхняя граница
  подтверждения на новом материале; строго односторонний).
- **H2 (поймал ли, позитивы):** sequence-level recall ≥ **90 %** пролётов (в пролёте ≥1 alarm-окно
  внутри помеченных границ) при n≥5.
- **H3 (скорость, TTD):** медиана TTD (граница «дрон виден» → первый alarm) ≤ **10 с**, p90 ≤ **20 с**.

## Вердикт-правило

«Подтверждено» := H0 ∧ H1 ∧ H2 ∧ H3 на однократном открытии. Любой красный — честная фиксация
(синтез/отчёт переписываются под фактическое число; политика не меняется, τ не ищется заново —
стоп-критерий). После it-87 эксперименты только для блокер/багов.

### Самопроверка вычислительных путей H1–H3 на синтетике (24.09, обвязка, не замер)

Smoke закрыл H0 и каркас, но позитивные пути (счёт пойманных пролётов в H2, медиана/p90 TTD
и фильтр alarm ∈ [gt_start, gt_end] в H3) не исполнялись ни разу: в smoke не было ни одного
реального позитивного GT (H2/H3 шли по ветке n=0/пустого списка). `research/it87_eval_selftest.py`
строит детерминированный синтетический набор (5 pos + 2 neg, окна 0,5 с, ручной расчёт
ожидаемых величин) и прогоняет **копию** боевого eval (единственная правка копии — sha-префиксы
заменены на префиксы фиктивных весов: коллизию sha256 подобрать нельзя; боевой файл не менялся).
Результат: 🟢 все пути совпали с ручной арифметикой — H1 40/402 зелёный; H2 4/5 = 80 % красный
(пойманный alarm вне GT-интервала не засчитан — фильтр работает); H3 медиана 3,0/p90 10,0 зелёный
(p90 = nearest-rank, при малом n conservatism в сторону max-ряда); CSV-колонки TTD/caught построчно.
Побочная находка самопроверки: расхождение первоначальной ручной гипотезы (p90=10 при ttd-ряду
с 58 с) с фактическим поведением eval (p90=58) подтвердило nearest-rank-формулу — интерпретация
гейта H3 на боевом материале: p90 считается по пойманным пролётам, единичный долгий пролёт
красит гейт (совпадает с формулировкой «p90 ≤ 20 с»). Артефакты: `it87_eval_selftest.py`
(в манифесте, 149 файлов); временные синтеты — /tmp, в реестр не входят.

### Пре-открыточный аудит runner'а (24.09, починки обвязки, не замер)

Ручной проход `it87_holdout_run.sh` перед единственно допустимым боевым пуском нашёл три
дефекта «молча испорченного однократного замера» (перезапуск сегмента после боевого пуска
запрещён протоколом — значит runner обязан ОТКАЗЫВАТЬ, а не продолжать с грязным срезом):

1. **CRLF-манифест**: `read` из файла записи автора мог утащить `\r` в поля `dur/ge`
   (поломка awk-арифметики таймеров) → чтение через `tr -d '\r'`.
2. **Таймаут дренажа без вердикта**: выход из цикла `DEADLINE` при `STABLE<45` продолжал прогон
   с обрезанным срезом → жёсткий ОТКАЗ (обрезанный срез = тихая порча H1/H2 однократного замера).
3. **Нет нижней границы длительности**: сегмент `dur<20` даёт `exp=dur−10≤0` и NaN-ratio в eval
   → гейт `dur≥20` на входе этапа.

Измерительный стек (веса/τ/режим/гейты H0–H3) не тронут — только отказные условия обвязки;
`bash -n` чист, гейт dur проверен (25/20→OK; 19,9/abc→FAIL), манифест пересобран (149, OK).
