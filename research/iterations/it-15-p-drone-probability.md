# ИТЕРАЦИЯ 15 — Вероятность класса p(drone) в AudioDetection (AST больше не теряет «насколько не дрон»)

- **Дата:** 2026-09-04
- **Цель:** устранить потерю информации, найденную в it-12: `ast_classifier.detect()` вычислял softmax-вероятность класса drone, но в `AudioDetection` писалась только пара (label, confidence) — для non-drone окон p(drone) обнулялась, что делало калибровку порога и энтропийные веса невозможными.
- **Компоненты:** `cnn.py` (+4 строки: опциональное поле `p_drone` в `AudioDetection`), `ast_classifier.py` (+1: заполнение поля), `services/acoustic-detector/tests/test_p_drone.py` (новый, 3 теста).

## Что сделано

- `AudioDetection.p_drone: float | None = None` — опционально, контракт не ломается (lwcnn пока отдаёт None; поле замороженного dataclass);
- AST `detect()` заполняет `p_drone` (softmax-вероятность класса drone) — оба класса теперь доступны;
- интеграционный тест на реальных весах и sandbox-аудио: на полёте (t=12 с) и стоянке (t=70 с) `p_drone` присутствует, согласована с парой (label, confidence), полёт ≫ стоянка; тест автоматически пропускается, если весов нет локально.

## Проверки

- 3/3 теста (11 с, включая загрузку модели); ruff по изменённым файлам чист (5 замечаний в `cnn.py`/`ast_classifier.py` — пре-существующие, на HEAD были до правки, вне скоупа).

## Что это открывает (следующие итерации)

1. **Проброс p_drone в контракт сообщений**: `InferenceMsg` (libs/common, schema_ver=1) пока не несёт p_drone — проброс потребует изменения контракта (решение за автором; AGENTS: контракты менять только в libs/common).
2. После проброса становятся возможны: честная калибровка порога по p_drone (it-12 сняла вопрос только для дискретной пары), энтропийные веса с реальной энтропией (H по softmax-паре, не по деградированной 0/1), детектор «детерминированности» канала для health-gate (it-14, дисперсия выходов).
3. lwcnn тоже может отдавать softmax-вероятность (logits 2 класса) — маленькое добавление, унификация бэкендов.

## Ограничения

- Поле не публикуется в Kafka (контракт не менялся) — до проброса p_drone живёт только внутри сервиса детекции и в тестах/диагностике.
- it-12 остаётся в силе: даже с p_dronerecall-проблема AST (уверенные non-drone) порогом не лечится — но теперь это измеримо (распределение p_drone вместо 0/1).
