# ИТЕРАЦИЯ 60 — Re-test motion-признака в SAHI-режиме на MMAUD: насыщение и отсутствие статичной фазы — признак не восстановлен

- **Дата:** 2026-09-06
- **Источник:** план it-59 §5 (при SAHI-кропе цель крупнее — проверить speed_rel); ревью §3.
- **Артефакты:** `research/mmaud_sahi_motion.py`, `research/mmaud_sahi_motion.csv` (офлайн-попытка), `research/tap_both.py`, `research/motion_tap.jsonl` (live-тап video.raw + inference), фикс `mmaud_replay.py` (media_ts — адаптер писался до it-34 и не имел медиа-времени; теперь ставит, с накоплением по loop).

## Попытка 1 (офлайн, argmax по срезам): насыщение из-за методологии

speed_rel через «best-conf детекция за кадр» (без мерджа и без трекинга) — медиана 1.000 в ОБОИХ состояниях. Причина: single-class модель даёт конкурирующие детекции (дрон 0.58–0.61 против артефактов крыши с близким conf) — argmax прыгает между ними → центр скачет ≫ bbox → кламп 1.0. NMS-мердж не помог (конкуренция между РАЗНЫМИ объектами, не дублями).

## Попытка 2 (live, per-track motion_score через ByteTrack): тоже насыщение, плюс дыра в статике

Live-прогон MMAUD (SAHI on, fps 2) с тапом video.raw+inference:
- **ЛЕТИТ (n=288): motion медиана 1.000, p90 1.000** — реальное быстрое перемещение: дрон пролетает собственную ширину быстрее, чем окно оценки (8 кадров ≈ 4 с при 2 fps), кламп 1.0 съедает верхний диапазон.
- **СТОИТ: 0 замеров** — статичная фаза секвенции всего 1.6 с (49 кадров @30 fps ≈ 7 wall-кадров при 2 fps): ByteTrack не успел активировать треки, офлайн-SAHI recall фазы был 0.584 conf, но треков нет.
- По пути: `mmaud_replay` не ставил media_ts (адаптер до it-34) — motion_score вычислялся только с media_ts; исправлено (медиа-время = позиция кадра / fps_nominal, накопление по loop).

## Вывод: motion_floor без изменения

1. **На этом материале speed_rel не разделяет «стоит/летит» ни в одной конфигурации** (полный кадр — it-52/53, SAHI — it-60): у летящего дрона apparent speed ≥ bbox_w/с (кламп), у статичной фазы нет треков. motion_floor остаётся 0.3 без практической роли (в presence-режиме не применяется, в airborne надёжнее аудио-подтверждение it-55).
2. Дискриминатор «активен» — **аудио-подтверждение (it-55)**; видео-признак состояния требует либо оптического потока (движение фона), либо обученного классификатора на размеченных состояниях, либо нескомпрессированного material с большей длительностью статики.
3. Организационное: загрузки MMAUD идут только вручную через браузер (капча на sharepoint) — V2/V3 при решении пользователя.

## Ограничения

- Статичная фаза 1.6 с — принципиально мало для треков; на материале с длительной статикой (V2/V3 Carpark) измерение повторить.
- Кламп motion_score в [0,1] — контрактный; расширение диапазона = несовместимое изменение семантики поля.
