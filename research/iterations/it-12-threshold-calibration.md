# ИТЕРАЦИЯ 12 — Калибровка порога AST: опровергнута, зато вскрыт нюанс маппинга p(drone)

- **Дата:** 2026-09-04
- **Цель:** проверить гипотезу it-09 (п.1): «порог по PR-кривой валидации поднимет recall AST».
- **Артефакт:** `research/threshold_calibration.py` (таблица F1(порог) для raw/медиана-5, соло/в late).

## Выводы

1. **Гипотеза калибровки порога опровергнута**: у AST на этом клипе бимодальное распределение p(drone) — значения либо ≈0, либо ≥0.55; между 0.05 и 0.50_scores нет, F1 плоский. 26 промахов — это **уверенные** классификации «non-drone», а не низкая уверенность. Recall добывается только временнóй фильтрацией (медиана: R 0.766→0.847) и переобучением (PETL, конфьюзеры — it-09), не порогом.
2. Для late порог 0.45–0.5 оптимален (текущий 0.5 — ок); снижение порога до 0.35–0.40 при глухом/шумном аудио впускает FP (окна с p_a=0 и p_v≈0.7 дают 0.5·p_v ≥ 0.35) — противоречит интуиции «ниже порог = выше recall», потому что неинформативное видео проваливает TRUE.
3. **Нюанс маппинга для патча**: в `ast_classifier.detect()` результат несёт только победивший класс (label, confidence) — при label='non-drone' p(drone) записывается 0.0 и информация «насколько не дрон» теряется. Для будущей калибровки/энтропийных весов стоит отдавать вероятности обоих классов (softmax-пара) — рекомендация в `research/patches/fusion_audio_median.patch.md` (дополнение).
4. Плоская F1-кривая аудио — также хорошая новость: система **нечувствительна к выбору порога в диапазоне 0.05–0.5** для аудиоканала — один источник хрупкости меньше.
