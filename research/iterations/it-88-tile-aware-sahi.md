# it-88 — tile-aware SAHI агрегация (exploratory) · ЗАКРЫТА отрицательно

Дата предрегистрации: 2026-09-24 (до всяких замеров; GPU-пуск строго после закрытия it-85).
Приоритет P2, статус в роадмапе (`DECISION-roadmap-post-it82.md`): опционально, exploratory →
затем только на holdout. Нумерация — фактический номер INDEX.

## Проблема (что хотим чинить)

Ансамбль `old⊕new CONF-AND@0,40` даёт зелёную пару 94,7 % recall / 7,2 % FP на **640-px
full-frame** негативном протоколе (канон E5×E1, it-74). На **чистых HD-фонах Open Images
(strict400, 400 кадров)** в том же SAHI-режиме (тайл 640, overlap 0,2) FP(AND@0,40) = **48,8 %**
(it-79/it-80) — см. `SYNTHESIS-ensemble.md` п.9: это зарегистрированная **граница применимости**
(режим входа), а не опровержение. Гипотеза механизма раздувания: max-conf по N тайлов — это
экстремальная статистика (больше испытаний на кадр → выше шанс хотя бы одного ложного пика);
FP растёт с числом тайлов и не компенсируется политикой.

## Гипотеза (одна проверяемая)

Если заменить per-frame агрегацию с MAX на **size-corrected** правило (согласие нескольких
перекрывающихся тайлов либо процентиль против эмпирического нуля по фоновым тайлам), то FP на
HD/SAHI смещается вниз к порогу E1 (≤12,8 %) **без обрушения** recall на полётных MMAUD-кадрах
(≥85 %). Реальный дрон, пересекающий границу тайла, виден в ≥2 перекрывающихся тайлах;
одиночный шумовой пик — в одном.

## Дизайн (предрегистрирован, менять после пуска нельзя)

Оси и материал (тот же tiling 640/0,2/STEP=512/conf=0,05, что it-73/it-79):
- **FP-ось (главная):** `strict400` HD-фоны Open Images (400 кадров, дрон отсутствует by
  construction → любое срабатывание = FP). Ряды: old (`yolov8s-uav.pt`) и new
  (`uav-yolov8s-bg-best.pt`).
- **recall-guardrail:** flight-кадры MMAUD (`z>1.0`), детерминированное подмножество
  **каждый 10-й** по sorted frame-id (n≈502; полный flight=5018, не гоняем тайлами — экономия).

Harness `it88_sahi_tiled.py` сохраняет на кадр: `n_tiles`, список `tile_confs` (row-major),
`tile_nboxes`, отдельный `full_conf640` (full-frame@640 resize-проход). Анализатор
`it88_tile_aggregate.py` — **ноль инференса** поверх дампов.

Политики per-ряд (кадр решается по одному ряду), ансамбль = AND двух рядов по тому же правилу:
- `MAX` := max(tile_confs) ≥ τ — базовый SAHI (для воспроизведения it-79).
- `CONS-k` := #{tiles ≥ τ} ≥ k, k∈{2,3}.
- `NULL` := #{tiles ≥ τ} ≥ c, где c = min{m: P[Binom(n_tiles, p̂_τ) ≥ m] ≤ α=0,05};
  p̂_τ — эмпирическая нуль-ставка фонового тайла (доля фоновых тайлов с conf≥τ, объединённая old+new).
- `FULL` := (max ≥ τ) ∧ (full_conf640 ≥ τ) — full-frame corroboration.

τ-сетка {0,30; 0,35; 0,40; 0,45; 0,50}; основная ячейка τ=0,40. One-tile-per-row-major —
согласие считается по числу тайлов (не по IoU-кластеризации боксов; это упрощение регистрируется
как ограничение метода).

## Сами-проверки (блокатор интерпретации; вердикт дефектного пуска не выносится)

- SC1: `MAX`-AND@0,40 FP на strict400 = **48,8 % ±3 п.п.** (блокатор воспроизведения it-79).
- SC2: `MAX`-old solo recall@0,5 на подмножестве ≈ **94,5 % ±3 п.п.** (блокатор канонов recall).
  Не пройдены → дамп дефектен (режим/веса/tiling), перемерить, вердикт не выносится.

## Гейт T1 (exploratory; единственный предрегистрированный вердикт)

∃ не-MAX политика с FP(AND@0,40) ≤ **12,8 %** ∧ recall(AND@0,40) ≥ **85 %** на своих осях?
- **Да** → КАНДИДАТ; подтверждение переносится на замороженный holdout (класс it-87). На
  dev-наборах (strict400/MMAUD) зелёный **переисключён** (adaptive reuse) — это exploratory
  evidence, не headline. it-88 НЕ закрывается как null; кандидат → в очередь holdout.
- **Нет** → exploratory-негатив: ни одна tile-aware агрегация не собирает угол. Граница
  применимости ансамбля (SYNTHESIS п.9) НЕ снимается. **Перекалибровка τ/политики запрещена
  стоп-критерием** (красный не триггерит новую сетку). it-88 закрывается отрицательно.

## Ограничения (регистрируются заранее)

- n_tiles зависит от размера HD-кадра (smoke-проверка кода harness на strict400: кадр
  2000×3008 → 24 тайла, 1280×960 → 6; т.е. **до ≈24–28** для крупных HD) — CONS/NULL корректны
  по числу испытаний, но перекрывание тайлов делает испытания зависимыми (автокорреляция); NULL —
  консервативная поправка, не точный перестест. Большая N — и есть механизм раздувания MAX-FP,
  который it-88 проверяет.
- recall-guardrail на подмножестве (n≈502) → биномиальный шум ±~1–1,5 п.п.; годен детектировать
  только крупное обрушение, не тонкую разницу политик.
- Материальное согласие соседей считается как «≥k тайлов ≥τ», без пространственной привязки боксов:
  два независимых ложных пика в разных тайлах удовлетворят CONS-2 (консервативно к FP).

## Итог (измерено 24.09; ЗАКРЫТА отрицательно — exploratory-негатив)

4 GPU-дампа (bg400 × {old,new} = 400 строк; mmaud stride=10 × {old,new} = 502 flight-кадра) →
ноль-инференс разбор `it88_tile_aggregate.py`. Нуль-ставка фонового тайла p̂_τ (объед. ряды, bg400):
0,30→15,4 %; 0,40→10,5 %; 0,50→6,6 %.

Сами-проверки (блокаторы интерпретации) — обе зелёные, харнес валиден:
- **SC1 🟢** MAX-AND@0,40 FP на strict400 = **48,8 %** ≈ канон it-79 48,8 ±3,0.
- **SC2 🟢** MAX-old solo recall@0,5 на подмножестве = **95,8 %** (порядок канонов 94,5 ±3).

**T1 🔴 (единственный предрегистрированный вердикт):** ни одна не-MAX tile-aware агрегация не
собирает угол FP(AND@0,40) ≤ 12,8 % ∧ recall(AND@0,40) ≥ 85 %. CONS3@0,40 даёт FP 19,0 при recall
69,9; CONS2@0,40 — recall 86,7 но FP 30,5; угол недосягаем. → **exploratory-негатив**: граница
применимости ансамбля на HD/SAHI (SYNTHESIS п.9: «однородной HD-точки нет») НЕ снимается;
**перекалибровка τ/политики не выполнена** (стоп-критерий: красный не триггерит новую сетку);
кандидат на holdout НЕ заявлен (условие «Да» не выполнено).

Оговорки (по §«Ограничения»): испытания тайлов зависимы (перекрытие) → NULL — консервативная
поправка, не точный перестест; recall-guardrail n≈502 (шум ±~1–1,5 п.п.) детектирует только
крупное обрушение; «≥k тайлов ≥τ» без пространственной привязки (консервативно к FP).
Результат подтверждает механизм раздувания MAX-FP (it-79) и не открывает нового рабочего режима.
