- **Дата:** 2026-09-21. **Статус: ЗАВЕРШЕНА. Вердикт по правилу: V1 ✅, V2 ✅, V3 ❌❌ → экспорт пары ЗАПРЕЩЁН,
  `models/visual/yolov8s-uav.pt` остаётся майским (sha `41f3fd55…`).**
- **Триггер:** вопрос автора «есть ли положительные варианты после красного E5 (it-65)»;
  пересчёт существующих артефактов (шаг 0) показал, что E5-регресс — сдвиг операционной точки.
- **Predecessors:** it-65 (вердикт КРАСНЫЙ по E5: SAHI-recall полёт 84,3 % < 89,5 % при τ=0,5),
  it-66 (в контуре «FP» 33/144 = верные детекции стоящего дрона), it-64 (дефект негативов).

## Шаг 0 — замер из существующих артефактов (ВЫПОЛНЕН 2026-09-21, CPU, новых прогонов не было)

Полный протокол и числа: `research/it69_thresh_shift_analysis.txt` (источники — `mmaud_sahi_full{,_new}.csv`
с per-frame `conf_sahi` при гейте инференса 0,05 и `coco_bg_fp_{old,new}.csv` с per-frame `max_conf`).

| τ гейта | recall полёт old | recall полёт new | FP COCO-фоны old | FP COCO-фоны new (n=90) |
|---|---|---|---|---|
| 0,50 | 94,5 % | 84,3 % | 25,6 % | 8,9 % |
| 0,45 | 98,7 % | 90,6 % | 27,8 % | 11,1 % |
| 0,40 | 99,8 % | **94,8 %** | 33,3 % | **11,1 %** |
| 0,05 | 100 % | 100 % | — | — |

**Механизм (измерен):** из 594 «потерянных» new-кадров при τ=0,5 — 415 (70 %) лежат в полосе
[0,40; 0,50), медиана 0,441; при τ=0,05 new видит 100 % полётных кадров. Т.е. COCO-негативы
сместили распределение conf ~на 0,1 вниз, **не отняв чувствительность**; вердикт E5 фиксировал
это как проигрыш только потому, что порог 0,5 был унаследован от старой модели без перекалибровки.
Пара (веса `uav-yolov8s-bg/best.pt`, гейт 0,4) доминирует точку (старые веса, 0,5) по обеим осям
в этом замере: recall 94,8 ≥ 94,5 и FP 11,1 ≤ 25,6; FP-полоса new плоская на 0,3–0,4.

## Честные ограничения шага 0 (почему это ещё НЕ результат)

1. **Post-hoc:** пересчёт тех же данных после красного вердикта; критерии ниже фиксируются ДО подтверждений.
2. **Одна семка обучения** (принцип ≥3 seeds): обобщение «рецепт→сдвиг» не доказано; доказываемое
   утверждение этой итерации слабее и проверяемо: «ДАННЫЙ чекпойнт при гейте 0,4 не хуже канона».
3. **Статмощность:** n=90 независимых фонов → 11,1 % ± ~6,6 п.п. (95 % ДИ ~6,4–18,6 %) — верхняя
   граница пересекает порог E1 12,8 %; без расширенного независимого замера вывод о FP не делается.
4. Красный E5 в конфигурации поставки (гейт 0,5) остаётся фактом — итерация не «отменяет» вердикт,
   а проверяет другую операционную точку.

## Протокол подтверждения (предрегистрируется СЕЙЧАС, до прогонов)

- **V1 (расширенный независимый фон, CPU):** новый выборка ~400 чистых фонов COCO val2017,
  ИСКЛЮЧАЯ 900 уже использованных id (720 в обучении + 90 val-отбор + 90 test-замер — все негодны);
  обе модели, τ∈{0,5; 0,4}. Критерии: FP(new, 0,4) ≤ 12,8 % И FP(old, 0,5) ∈ 25,6 % ± 5 п.п.
  (контроль переносимости базы). Требуется загрузка публичного val2017 (данные — на машину, не с машины).
- **V2 (независимость recall):** MMAUD-SAHI-подтверждение нарезкой пополам по времени сессии
  (кадры 0–2545 калибровка, 2546–5091 контроль — пороги по калибровочной половине, проверяется
  на контрольной): recall полёт new@0,4 на контрольной половине ≥ 89,5 % (тот же порог E5).
- **V3 (контур, GPU):** живой прогон песочницы (протокол it-66, `--suffix=-new-gate04`):
  новые веса + детекторный гейт 0,4, fusion τ=0,5 и pilot.yaml (watermark/k=5) без изменений.
  Критерии по образцу it-66: recall airborne-окон ≥ старых весов − 0,02; F1(поздний) ≥ 0,95;
  медиана задержки ≤ старой + 1,0 с; presence-FP на стоящем дроне НЕ засчитывается ошибкой
  (урок it-66; целевая переменная presence — `DECISION-target-variable.md`).
- **Правило вердикта:** все V1–V3 зелёные → экспорт пары (чекпойнт + гейт 0,4) разрешён:
  `train`-конвейер `evaluate/export` с фиксацией sha, ключ конфига детекторного гейта в `pilot.yaml`,
  запись в `models/registry.csv` и `models/README`; ЛЮБОЙ красный → веса остаются майские,
  в отчёте фиксируется «рычаг перекалибровки исчерпан на независимой проверке».

## Уточнение протокола ДО прогонов (2026-09-21, после одобрения автора, до V1–V3)

Найдено при подготовке V3: **боевой детекторный гейт в поставке — 0,25** (`pilot.yaml:78
conf_threshold`, `factory.py:18` тот же дефолт), а не 0,5. Оффлайн-сетка E5 (0,5) —Research-конвенция,
в проде никогда не действовала. Следствия, фиксируемые ДО замеров:
1. V3 плечи: **A — канон (старые веса @0,25, it-55/66 числами)** против **B — новые веса @0,4**;
   пороги B не меняются (recall ≥ A−0,02; F1 поздн. ≥ 0,95; задержка ≤ A+1,0 с; presence-FP не ошибка).
   Плечо «новые @0,25» = уже измеренный it-66 кандидат — не повторяем.
2. К V1 добавляется отчётная точка FP при 0,25 (обоими весами) — сетка CSV её содержит;
   критерии V1/V2 остаются как предрегистрированы (0,4/0,5), 0,25 — справочно.
3. Мелкая находка по песочным CSV (`yolo_sandbox_frames_new.csv`): new-модель ни одной
   airborne-секунды не роняет max_conf ниже 0,25 (105≥0,5; 4 в [0,4;0,5); 1 в [0,25;0,4)),
   т.е. потеря 6 окон it-66 — не «низкий conf поштучно», а эффект оконной логики/трекинга;
   V3 обязан показать, воспроизводится ли она при гейте 0,4.

- **V3:** `bash research/it69_v3_run.sh` (гейт-предфильтр max_conf<0,4→0 + 5 fusion-скриптов
  `--suffix=-new-gate04`, лог `research/it69_v3_run.log`). Ключевая находка: **выходы V3
  побайтово совпали с it-66 (new @ 0,05)** — на песочном материале все airborne-секунды new при
  imgsz 480 имели conf ≥ 0,4, т.е. гейт 0,4 в контуре — no-op, а потеря 6 airborne-окон —
  **не пороговая**, а следствие оконной логики fusion/трекинга (окна, где медиана pv по окну < 0,5).
- **Вердикт по предрегистрированному правилу («ЛЮБОЙ красный → веса остаются майские»):**
  пара (best.pt, 0,4) **не экспортируется**. Рычаг перекалибровки подтверждён офлайн на
  независимых данных (FP в 2,7 раза ниже канона при recall 97,1 %) и **опровергнут на уровне
  контура**: контурные потери новых весов — не conf-гейт, а окна с низкой медианой pv.
  Направление починки смещается с операционной точки на рецепт (доля/природа негативов,
  distant-негативы) и/или увеличение доли мелкотаргетных позитивов в корпус.
