# it-84 — Exact paired replay: парный FP-замер AND@0,4 против old на тех же 400 кадрах (ПРЕДРЕГИСТРАЦИЯ 24.09, до любых замеров)

**Гипотеза.** На строго идентичном материале (одни и те же 400 HD-фонов OI, один и тот же
порядок, loop=off) попоточное сопоставление кадров подтверждает направление it-82:
AND@0,4 гасит больше ложных срабатываний одиночного old, чем добавляет — discordant-пара
b (A+/B−) > c (A−/B+) со статистически значимым сдвигом (McNemar exact p ≤ 0,05),
а cluster-bootstrap интервал Δ = FP(B) − FP(A) не накрывает 0.

**Зачем (дыра после it-82/83).** it-82 сравнивал две независимые выборки из одного
распределения (234 против 199 уникальных кадров, петли ×1,2) — ДИ Уилсона там оптимистичны
и не paired (ограничение зафиксировано в канон-блоке). Аудит 24.09 (P1) требует paired-версию
как главное доказательство FP-подавления; media_ts-фикс it-83 сделал кадр идентифицируемым
(media_ts = номер кадра / fps при loop=false → естественный join-ключ без правки схемы).

## Материал и механизм

- Тот же strict400 (400 симлинков Open Images по filelist.txt, §6k), mmaud_replay, fps=2,
  **loop=false** → детерминированный конечный список из 400 кадров = медиа-окно 200 с;
  аудио выключено (video-only, как it-82/83 — изолированный видео-FP, NOT боевой профиль).
- Этапы: **A vote=off** (old-only) → **B vote=and floor 0,4** (voter uav-yolov8s-bg-best);
  один runner, та же пересборка/гейты it-81/82/83 (build образа, топики, P5 env,
  стрим-гейт 25 с, P4 model_name по данным). OR не включаем: его живой исход насыщен
  (it-82 C=1,000), центральный claim — paired AND vs old.
- **Дренаж (урок it-83):** SCORE_OFF этапа берётся не по wall-таймеру, а когда поток решений
  стих: offset decisions.jsonl не растёт ≥ 45 с после того, как источник дописал кадр 400
  (источник грузит ~200 с; таймер ожидание — до 300 с, потом ОТКАЗ). Иначе хвост кадра
  попадает в один срез и не попадает в другой.
- Burn-in НЕ применяется: в paired-дизайне кадр либо сопоставлен, либо выпал (см. C1);
  переходные эффекты тёп-запуска атрибутируются C1, а не вырезанием окна.

## Критерии (предрегистрированы)

- **C1 (комплектность — гейт прогона, не результат):** coverage-факт, измеренный на данных
  it-83 ДО этого прогона: fusion порождает решения не по каждому 0,5-с окну, а по
  детерминированному подмножеству (~56 % кадров; срезы it-83: |A∩B|=164 при |A|=167, |B|=165 —
  фаза детеминирована между этапами, симметрична). Поэтому paired-множество = покрытые кадры,
  а не все 400: **требование |A∩B| ≥ 180 и |only_A|, |only_B| ≤ 15**; невыполнение = потеря
  кадра в контуре — прогон не засчитывается, чинится харнес. Полный список выпавших
  (общий интервал минус покрытые) печатается в summary.
- **P1 (эффект AND, paired):** b > c и McNemar exact p ≤ 0,05, причём Δ < 0.
- **P2 (согласие с it-82):** знак совпадает (b > c) и paired-оценка FP(A) в интервале
  [0,5; 1,0] — порядок it-82 (0,893) не обязан совпасть численно (каждый кадр один раз,
  без усреднения по петлям), но качественное направление обязательно.
- **P3 (атрибуция конфигурации):** P4/P5-гейты it-83 зелёные на обоих этапах (env, model_name
  по данным); sha весов в логе.
- Вторичное (не критерий): cluster-bootstrap Δ по кадрам (10 000, seed 8404) — фиксируется
  с интервалом; overlap с 0 трактуется честно как «в пределах разрешённого разброса».

## Метрика и артефакты

Единица — кадр (уникальный media_ts), положительный = любое decision=true по нему
(union-семантика). GT тривиален: все 400 кадров бездронные. Discordant-таблица b/c/оба+/оба−,
McNemar exact (двусторонний биномиальный), bootstrap ДИ Δ — `research/it84_paired_eval.py`
(смоук-тест на синтетике: b=4/c=0 → p=0,125 ✓, C1 на несовпадении множеств ловит ✓).
Артефакты: `it84_paired.csv`, `it84_paired_summary.txt`, лог `it84_paired_run.log` (gitignored).

## Риски / ограничения (фиксирую ДО)

1. Потеря стартовых кадров (~10–12/этап) смещает FP вверх/вниз только если выпавшие кадры
   систематически «удобнее» для одного плеча — при одинаковом порядке выпадение симметрично
   (гейт C1), но полный список выпавших кадров печатается в summary для контроля.
2. Один прогон, одна модель-пара, один материал — paired убирает выборочный шум между
   плечами, но не переносимость на другие HD-наборы (формулировка: «на 400 размеченных
   фонах OI в живом full-frame контуре»).
3. if-then по C1: если источник при loop=false всё-таки зацикливается (находка харнеса),
   прогон останавливается до измерений и переделывается — это не «красный результат».
4. ДИ Уилсона маргинальных FP при paired-дизайне не являются тестом (перекрываются по
   конструкции) — тест только McNemar/bootstrap.

## Ожидаемый итог и что дальше

Зелёный P1: FP-подавление AND@0,4 перестаёт быть «не paired» — канон-блока ограничение
it-82 снимается, SYNTHESIS пункт 9 уточняется ссылкой на paired-числа; это финальное живое
обоснование AND_presence_live до frozen holdout (it-87). Красный при зелёном C1: paired-оценка
не подтвердила независимую (234/199) — пересмотр формулировок it-82 в отчёте обязателен.
