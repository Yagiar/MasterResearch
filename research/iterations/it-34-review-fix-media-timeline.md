# ИТЕРАЦИЯ 34 — Фикс по ревью: общий медиатаймлайн источника — proto + симулятор + gateway (§6.1)

- **Дата:** 2026-09-05
- **Источник:** внешнее ревью GPT-6-Astra (`review-from-gpt-6-astra/MasterResearch_review.md`, п. 6.1).
- **Компоненты:** `libs/proto/.../ingest.proto` (+`media_ts` в Frame/AudioWindow, стабы перегенерированы `make proto-gen`), `libs/common/.../messages.py` (+`media_ts` в VideoRawMsg/AudioRawMsg), `source-simulator`: `adapters/base.py`, `adapters/media_file.py`, `controller.py`, `grpc_client.py`, `ingest-gateway/normalizer.py`; новые тесты `source-simulator/tests/test_media_file_media_ts.py` (+5), `ingest-gateway/tests/test_normalizer_media_ts.py` (+4).

## Дефект (подтверждён по коду)

1. `MediaFileAdapter.frames()` читал **каждый** кадр файла, а отправка шла по запрошенному FPS: файл 25 FPS при отдаче 5 FPS растягивал видео-содержание в 5 раз.
2. Аудио двигалось своим шагом (hop). Контроллер проставлял обеим модальностям wall-clock момент отправки: близкие `ts` не означали, что модальности описывают один момент сцены. При loop рассинхрон накапливалась от прохода к проходу.

## Решение (часть 1 из 2; fusion/скоринг — it-35)

1. **Страйд кадров**: `_frame_stride() = round(file_fps / requested_fps)` — отдаётся каждый N-й кадр, содержание идёт со скоростью запрошенного FPS; медиа-шаг кадра ≈ 1/requested_fps = общий темп с аудио.
2. **`media_ts` в обеих модальностях** — монотонная позиция на таймлайне исходного медиа (с от старта источника), с накоплением длительности по loop-проходам: видео = `(media_base + fi) / file_fps`, аудио-окно = `media_base + offset/sr` (конец окна = `media_ts + len_ms/1000`). Проброс: `FrameItem/AudioItem` → proto `media_ts` (аддитивные поля 9/10) → `VideoRawMsg/AudioRawMsg.media_ts` (опционально, `schema_ver: 1` сохранён, прецедент it-18).
3. `ts` остаётся wall-clock (для e2e-латентности) — теперь это явно разделённые величины: время доставки ≠ время события.
4. Адаптеры без понятия медиа-времени (synthetic) отдают `media_ts=None`/0 — приёмник трактует 0 как отсутствие.

## Тесты

- Файл 25 FPS @ отдача 5 FPS: ровно каждый 5-й кадр, `media_ts` шаг 0.2 с (было бы растяжение ×5).
- Медиа-время монотонно сквозь loop (0 → 0.4+).
- Аудио-окна несут позицию начала; шаг = hop.
- Контроллер: `ts` wall-clock, `media_ts` без изменений; gRPC-клиент и normalizer пробрасывают поле; `media_ts=0` → None.

**55/55 passed** (монорепо), ruff чист по затронутым файлам.

## Ограничения

- Запрошенный FPS **выше** файлового не ускоряет содержание (страйд=1, медиа-время идёт медленнее wall-clock) — расхождение теперь ИЗМЕРИМО по `media_ts`, но не компенсируется; документировано.
- Детекторы/inference/fusion пока не потребляют `media_ts` (проброс до decisions + перевод выравнивания и GT-скоринга на медиа-время = it-35). Исторические прогоны it-30 без media_ts — ретроспективно не выправить.
