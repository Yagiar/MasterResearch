## Главный тезис аудита (принят)

Цикл it-01…82 перевести из режима «ищём ещё метрику» в режим **заморозки и подтверждения**:
все it-01…82 объявляются development/exploratory evidence; далее — чинящие валидность работы
(media_ts, paired replay, throughput, мультимодальный негатив) и **один замороженный
confirmatory holdout** на материале, который цикл никогда не видел. После holdout — стоп
экспериментов (новые допустимы только для блокер/багов).

## Терминологические решения аудита (приняты, обязательны для отчёта/диссертации)

1. **Разыменование политик:** `OR_event_offline` (it-75, F1 0,961→0,965 — только offline
   event-протокол), `AND_presence_live` (it-81/82 — боевая гипотеза), `OR_presence_live`
   (опровергнутый контроль, 100 % FP в it-82). Формулу «контур=OR» без имени политики из
   текстов убрать — внешнего противоречия «OR рекомендован ↔ OR 100 % FP» комиссия не увидит.
2. **Operating point = f(режим инференса):** числа всегда с режимом входа; формула «модель
   имеет FP=7,2 %» запрещена, канон — «политика old⊕new CONF-AND@0,40: 7,2 % на 640/
   full-frame негативном протоколе; в SAHI-HD — 48,8 %; однородная HD-точка отсутствует».
3. **Target-Variable column:** в каждой итоговой таблице — столбец target
   (flight/E5 vs presence vs event/contour); 94,7 % и live R=1,000 не ставить в один ряд.
4. **Мультимодальность:** тезис «fusion лучше обеих модальностей» не утверждать (it-40/41:
   audio-only при своём пороге 0,978, превосходство слияния на пилоте не установлено);
   канон — комплементарность отказов + управляемая деградация через adaptive gating.
5. **Цена ×2:** до it-85 писать «медианная e2e-задержка в it-81 не отличалась; влияние на
   устойчивую входную частоту не измерено (при 2 к/с покрытие ~57 % — it-82)».
6. **Статистика it-82:** «ДИ не перекрываются» — не главное доказательство (234 vs 199
   кадров, автокорреляция); подтверждение несёт paired replay it-84 (discordant pairs,
   bootstrap по frame-id).
